This document is the constitution of the project: every design
decision derives from it, and amendments land here before they land
in code. Public-facing prose (README, user docs) follows the Google
developer documentation style guide; this spec favors normative
precision over style where the two conflict.

* 1. Purpose and scope

rmpc-auto-theme generates a complete rmpc theme from the currently
playing album's artwork and applies it to running rmpc instances
without restart, while guaranteeing WCAG-verified readability for
every generated color role.

Identity (rev 0.9, owner-ratified): the system is an EVENT-BASED
RETHEME ENGINE, not a colorizer. Because the theme document rmpc
accepts over IPC describes the entire UI — layout included — and
the hook fires per player event, any per-event reconfiguration of
the interface is in scope of this architecture without structural
change. Colors are the first application; per-track layout
variation (e.g. DQ-2, lyrics-conditional panes) is the same
mechanism pointed at a different part of the document.

In scope: color extraction, role assignment, theme emission, the
song-change trigger path, and application to rmpc ≥ 0.11. Out of
scope: rmpc layout/tab design (static user config; see §8), the
rmpcd plugin host (§9), and any rmpc fork or patch (ruled obsolete
rev 0.1; the v1 patches were repaint workarounds, not application
mechanisms).

* 2. Color doctrine (normative)

Ruled rev 0.1, owner-confirmed: *values are truth; colors are mapped
onto values.* Operationally — *own lightness, harvest hue*:

- Each color role owns a fixed OKLab lightness (tone) band, chosen so
  that the role's WCAG contrast minimums against its counterpart
  roles are satisfiable by construction before any art is seen.
- Art contributes hue and chroma only. Extracted cluster colors are
  projected into the target role's tone band (L replaced, hue held,
  chroma gamut-compressed as needed) rather than accepted at their
  native lightness.
- Guardrails (§5) therefore act as verification, not rescue. The v1
  pattern of accepting art lightness and ladder-searching to repair
  contrast afterward is retired; ladder search survives only as a
  last-resort fallback inside synthesis.
- Neutrals are legitimate: when art chroma is below the neutral
  threshold, roles fall back to the configured neutral ramp rather
  than inventing chroma.

* 3. Architecture

One short-lived generator process per song change; no daemon.

#+BEGIN_EXAMPLE
on_song_change hook (sh, thin)          rmpc-theme-gen (Rust binary)
  art-hash short-circuit          ┌────────────────────────────────┐
  rmpc albumart -o - ───────────► │ 1 extract  (color-core crate)  │
  exit 0 on all failures          │ 2 assign   (role solver)       │
                                  │ 3 emit     (base-theme patch)  │
                                  └──────────────┬─────────────────┘
                                                 ▼
                                  rmpc remote --pid $PID set theme -
                                  (+ optional OSC 11 terminal bg)
#+END_EXAMPLE

The hook receives rmpc's env payload (=$FILE=, =$PID=, tag vars) and
targets the emitting instance via =--pid=. The generator reads art
bytes on stdin and writes a complete theme document on stdout;
side-effect-free except logging. All policy lives in the binary; the
hook stays under ~60 lines.

* 4. Extraction engine

The engine is =color-core=: a tauri-free crate carved from
=~/git/color-tool-kmeans= (workspace member there; consumed here by
path dependency, later git dependency). Never copy engine files into
this repo — the v1 copy diverged and rotted (ruled rev 0.1).

Contract (from the parent's current pipeline, which is normative):
- OKLab-only clustering (k-means++, SoA/SIMD, deterministic seeds).
- Alpha-aware sampling with quality presets; default preset 2.
- Radius-guarded agglomerative cluster merge (dedup).
- Chroma-compressing gamut mapping that preserves L and hue.
- Output: clusters as {oklab, oklch, rgb, share}, dominance-ordered.

Attribution: =color.rs= carries CC BY 3.0 credit (Laurent Jégou,
Color-tool); the obligation travels with the crate.

* 5. Role model and guardrails

Eight primary roles: background, text, accent, active, highlight
text, frame, header accent, inactive. Derived roles are explicit
aliases (inactive = frame; progress: elapsed = active, track/thumb =
frame; scrollbar = frame on background — rev 0.5, prose reconciled
to the authoritative §6 binding map after the round-2 submission
flagged the divergence; the §6 table always wins).
The emitted template touches ≈9 tokens and nothing else.

Guardrail floors (defaults; config-overridable, §7) — carried from
v1 where they were proven in daily use:
| pair                    | minimum        |
|-------------------------+----------------|
| accent vs background    | 4.5:1          |
| text vs background      | 4.5:1          |
| active vs background    | 3.5:1          |
| highlight text / active | 4.5:1          |
| frame vs background     | 3.0:1          |
| peer ΔE (CIE76)         | 25             |
| hue separation          | 30° (chroma-gated; neutrals exempt) |

Contrast is WCAG relative luminance computed on sRGB, never an L*
proxy. The pairwise accent×active solver (strict → relaxed →
best-effort passes) is retained from v1, as is per-role provenance
(=origin=, =confidence=, measured contrasts) surfaced by =--debug=.

Default tone bands (rev 0.3; config-overridable at AI-IMP-003, OKLab
L, target with permitted band). The bands are SEARCH
BOUNDS, not proofs (rev 0.4 — rev 0.3's satisfiable-by-construction
claim is withdrawn: OKLab L bounds perceptual lightness, not sRGB
relative luminance; witnesses on record in the round-2 STOP —
highlight L .18 vs active L .60 reached 3.984:1, frame L .48 vs
background L .16 reached 2.506:1 at adversarial hue/chroma). The
solver verifies every WCAG pair on FINAL gamut-mapped sRGB outputs
and chroma-compresses or synthesizes within the bands until the
floors pass; a role that cannot pass falls to the neutral ramp. The
property test asserts, over the fixture corpus plus randomized art:
(a) every emitted role's L lies in its band, and (b) every emitted
WCAG pair meets its floor.

| role           | target L | band        |
|----------------+----------+-------------|
| background     |     0.13 | 0.10 - 0.16 |
| text           |     0.88 | 0.82 - 0.93 |
| accent         |     0.74 | 0.68 - 0.80 |
| active         |     0.65 | 0.60 - 0.70 |
| highlight text |     0.14 | 0.10 - 0.18 |
| frame          |     0.52 | 0.48 - 0.58 |
| header accent  |     0.76 | 0.70 - 0.82 |
| selection      |     0.75 | 0.72 - 0.82 |
| inactive       | = frame (alias) |      |

Selection (rev 0.8, from DQ-1 — cursor row vs playing row must be
distinguishable in VALUE, owner-ruled): a DERIVED role, not
art-harvested — C/h taken from the emitted active color, desired
L = clamp(active.L + 0.10, band), gamut-mapped, then verified on
final sRGB bytes. Hard floors: highlight text / selection >= 4.5:1,
and final selection.L - active.L >= 0.08 (an absolute band alone
can collapse; witness #0ab4be vs #2ac0ca, ΔL 0.037). Both-neutral
inherits hue with C <= 0.04 but keeps BOTH floors — the 743,580-case
round-1 sweep found no exemption hole (min ΔL 0.098, worst
highlight/selection 7.32:1). Provenance: derived:selection(active).
Config: bands.selection, floors.highlight_selection,
floors.selection_active_delta_l.

Highlight text is a DARK band by design: active is a mid-tone
background and 4.5:1 over it is only constructible from below.

Neutral doctrine (rev 0.3): art chroma below OKLch C 0.04 sends the
affected role to the neutral ramp — the same L bands with chroma
clamped to <= 0.02, hue inherited from the art's most chromatic
cluster when that cluster's C >= 0.02, else hue 250 (slate). The
ramp is the terminal fallback; its WCAG compliance is constructible
(near-neutral Y is hue-independent) and still test-verified.

Neutral peer exemption (rev 0.4): a peer pair whose members BOTH
emit at C <= 0.04 is exempt from peer ΔE and hue separation — the
pair is distinguished by lightness, provenance records =neutral=.
A pair with exactly ONE neutral member: hue separation exempt (the
chroma gate), peer ΔE floor stands. WCAG floors are never exempt.
(Rev 0.3 exempted neutrals from hue only; the round-2 STOP showed
the ramp cannot reach ΔE 20 at C <= 0.02 — witness ΔE 10.575 at
the ruled targets — so demanding it was demanding invented chroma.)

Solver tiers (rev 0.3): the four WCAG contrast floors are HARD at
every tier — no pass may emit below them; synthesis (ladder search
as last resort, per §2) must produce a compliant color or the role
falls to the neutral ramp. Peer ΔE and hue separation may relax by
tier with provenance recording the tier used: strict ΔE 25 / hue
30°; relaxed ΔE 20 / hue 20° (supersedes v1's mixed 25°/20°
CIELAB-era values; v2 measures hue in OKLch).

* 6. Theme emission

- The generator parses the user's base theme with the =ron= crate,
  patches color tokens only, and emits a COMPLETE theme document.
  Rationale (verified against rmpc 0.11 source): =UiConfigFile= is
  =#[serde(default)]= — omitted fields reset to built-in defaults,
  not to the loaded theme, so partial documents destroy user layout.
- Emitted documents keep the three RON pragmas (=implicit_some=,
  =unwrap_newtypes=, =unwrap_variant_newtypes=).
- Colors are emitted as 7-byte hex (=#rrggbb=) only; rmpc accepts no
  shorthand or alpha forms.
- The base theme defaults to the SHIPPED V3 PAIR (rev 0.11, DQ-3
  ruling implemented by AI-IMP-006): a genericized copy of the
  owner's v3 base — np_header, tab chrome, frame-colored Lyrics
  separator, materialized reset literals, no personal paths — with
  a matching sample config.ron beside it (four tabs, keybinds,
  hook vector and Pane(Cava) both present but commented; README
  carries the cava fifo setup procedure). The shipped base carries
  every mapped path (34/0 by construction). Chrome completeness
  (DQ-4): the round-1-ratified role table covers volume
  slider/percent/thumb (accent) + track (frame), [Playing]/artist
  (header_accent), [zxcv] states (frame/header_accent/accent),
  NORMAL (active bg + highlight_text fg), INSERT (accent bg +
  highlight_text fg), separator rule and label (frame); slider and
  cava =bar_color= styles are materialized before mapping; album
  table style is mapped. EXEMPTION: level severity colors stay
  literal — they are semantic (the color is the signal; an
  error-red rethemed to album-amber stops meaning error). The DQ-4
  law reads: no literal CHROME color survives a full retheme;
  semantic severity colors are exempt by this ruling.
- Patching mechanics (rev 0.3): serde round-tripping is FORBIDDEN as
  the emission path — ron 0.12 re-serialization drops pragmas,
  reorders content, expands defaults, and cannot preserve comments
  (round-1 finding). =emit.rs= is a span-preserving token rewriter:
  lex the RON document, track the named-field path, and rewrite ONLY
  the string literals at mapped paths; every other byte of the input
  (layout, comments, whitespace, ordering, pragmas) passes through
  untouched. A typed parse of the OUTPUT validates well-formedness;
  golden tests are byte-exact.
- A mapped path whose value is =None= or absent is left untouched and
  reported in =--debug= provenance (user intent respected); the
  shipped default base theme carries every mapped path.
- Binding map (rev 0.3; "~9 tokens" always meant the eight roles —
  this table is authoritative, occurrence count is incidental):

| path                                   | role                        |
|----------------------------------------+-----------------------------|
| background_color                       | background                  |
| header_background_color                | background                  |
| modal_background_color                 | background                  |
| text_color                             | text                        |
| borders_style.fg                       | frame                       |
| highlight_border_style.fg              | frame                       |
| current_item_style.fg / .bg            | highlight text / active     |
| highlighted_item_style.fg / .bg        | highlight text / selection  |
| tab_bar.active_style.fg / .bg          | highlight text / active     |
| tab_bar.inactive_style.fg / .bg        | inactive / background       |
| preview_label_style.fg                 | header accent               |
| preview_metadata_group_style.fg        | header accent               |
| level_styles.info.fg                   | accent                      |
| level_styles.*.bg                      | background                  |
| progress_bar.track_style.fg / .bg      | frame / background          |
| progress_bar.elapsed_style.fg / .bg    | active / background         |
| progress_bar.thumb_style.fg / .bg      | frame / background          |

* 7. Trigger, application, and failure policy

- Application channel: =rmpc remote --pid $PID set theme -= (stdin).
  VERIFIED 2026-08-19 on the owner's machine: file-write hot reload
  does NOT fire on macOS (the watcher filters on inotify close-write
  semantics; FSEvents/kqueue never emit them), so IPC is the ONLY
  application channel on macOS, not merely the preferred one.
  Ordering when both change: set theme BEFORE set config, or new
  tabs referencing new components fail conversion.
- Upstream bug (verified, minimal repro; fixed in upstream
  Unreleased): 0.11.0 =debuginfo= falsely reports "Missing
  component" for user components referenced from config tabs — it
  validates tabs against the DEFAULT theme's components. The TUI
  itself is unaffected. v2 tooling MUST NOT use =debuginfo= as a
  config validator on 0.11.0.
- Art acquisition (rev 0.11 identity fence): art MUST be fetched
  addressed by the ADMITTED file identity (MPD =albumart= /
  =readpicture= by URI), never by implicit current song — a
  mid-fetch track switch must not label B's bytes with A's
  identity. =rmpc albumart -o -= remains acceptable only where the
  admitted identity is re-verified at admission-token recheck;
  exit codes 0/1/2/3 are honored (3 = no song → exit). Exit 2 (no art), rev 0.7 ruling:
  the hook applies the UNMODIFIED base theme through the same
  write-then-apply path and clears the art-hash state, so the next
  track with art regenerates. No-art tracks read as the base look,
  never as the previous album's leftovers.
- Short-circuit: SHA-256 of art bytes; unchanged hash exits before
  extraction (same-album tracks must not regenerate or flicker).
  Missing hash tool degrades to always-regenerate, never to failure.
- Persistence (rev 0.6, owner-ruled): the hook writes the generated
  document to a theme file that config.ron references AND applies it
  via IPC in the same run (write first, then apply). An rmpc restart
  therefore wakes already themed, and the art-hash short-circuit
  stays valid across restarts. The base theme is never overwritten —
  generated output lives in its own file.
- Failure policy: the hook exits 0 on every failure path; theming
  must never disrupt playback. Errors log to a single capped file
  (unlike v1's unrotated 16 MB log).
- Determinism: fixed seeds end-to-end; identical art bytes produce
  an identical theme document.
- Optional OSC 11 terminal-background sync, gated on a writable
  =/dev/tty= and on config; ships DISABLED by default (rev 0.6,
  owner-ruled). Rev 0.7 seam ruling: the generator binary stays
  side-effect-free (§3 clause stands) — it gains a config-query
  mode (=--print-config KEY= over the effective flags+file merge)
  and the HOOK owns the actual =/dev/tty= OSC write. The =toml=
  crate is an approved dependency; §5 bands and floors move from
  constants to config-plumbed values with the SPEC numbers as
  defaults.
- Base-theme materialization (rev 0.7): the 16 mapped paths that
  are None/absent in the owner's base theme are to be MATERIALIZED
  with visually-equivalent literals (v3 doctrine: the auto-theme
  tints all space; an unpatchable None defeats it). The RL applies
  this to the live pair and archive; owner visual confirmation
  rides the Wave 2 smoke.

* 8. Boundary with the UI redesign

The canonical layout (rev 0.7 — reconciled to what the owner
actually ratified and runs) is the v3 Linux-recreation
(2026-08-20, personal-theming 245bc4e) plus the two-column Lyrics
tab (2026-08-27): tabs Now Playing / Library / Lyrics / Search on
keys 1-4, VISIBLE tab bar (owner overruled the hidden bar after
living with it), global np_header strip, pixel-square art band, no
Cava. The four-view/hidden-bar design this section previously
described is superseded; its record lives in
=~/git/personal-theming/RAG/design/handoff.md=. Static user
configuration remains owned there: =tabs:= and keybinds in
config.ron, chrome =layout= in the base theme. This project never
emits layout, tabs, headers, or formats. Verified against 0.11:
tabs belong in config.ron; the tab bar hides by omitting
=Pane(Tabs)= from the theme layout (=tab_bar.enabled= deprecated).

* 9. Paths not taken and future work

- rmpcd Lua plugin host: the natural long-term home (song_change
  hook, =mpd.read_picture=, =process.spawn=), but upstream declares
  it unstable. Revisit when rmpcd stabilizes.
- =album_art.custom_loader=: a two-way art hook worth evaluating for
  a zero-copy pipeline once the v2 baseline ships.
- Multi-terminal recoloring (pywal-style OSC sequences beyond
  background) — out of scope for v2.
- Prior art surveyed rev 0.1: pywal/pywal16, wpgtk, wallust,
  matugen. None combine art extraction with WCAG-verified role
  assignment; matugen's fixed-tone palettes inspired §2.
